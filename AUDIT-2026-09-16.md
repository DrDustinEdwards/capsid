## 2. How advanced is it?

Against systems that actually exist:

1. **Mem0 / Letta / Graphiti.** Those extract memory and retrieve it. Capsid stores typed documents and searches with FTS5. No vectors. No automatic extraction. Typed edges are five kinds in `document_links`, not a graph database. `docs/schema.md`; `migrations/0002_document_links.sql`. Capsid is stricter about writes and weaker at recall.
2. **Claude Projects / ChatGPT memory.** Those are product memory. Capsid is an operator's wiki with confirmation, `if_match`, versions, and an audit row. More control, more ceremony, no ranking model.
3. **Official GitHub MCP.** Broader API. Capsid is narrower: mapping as auth, blast-radius flags, `guardedWrite` as the only GitHub mutation site. `src/tools/repo.ts:86-155`; `src/scope.ts:144-152`.
4. **Temporal / Inngest / LangGraph Platform.** Those run durable workflows. Capsid jobs are a signed handoff plus a lease. No retries, no sagas, no child workflows. `src/jobs-schema.ts:9-26`.
5. **OpenHands / SWE-agent / Aider.** Those run the agent. Capsid writes a signed task document and scores in CI. The Worker cannot spawn a process. `docs/improve.md:22-26`.
6. **DSPy / GEPA.** Those optimize prompts. Capsid's loop, if turned on, changes source and keeps only a score improvement that does not regress pinned anchors. `docs/improve.md:38-52`.
7. **Cloudflare `McpAgent`.** Stateful Durable Object agents. Capsid uses stateless `createMcpHandler`. `src/index.ts:2`, `39`.
8. **Standing.** The work queue, scope model, and write invariants are built and used. The improve loop, skill lifecycle, and auto-merge machinery are built. The loop has never completed a run. Auto-merge is signed on for capsid as of `dcde046a`. Test files: 113 under `test/` plus 11 integration, against about 19k lines of `src/`. It is not a product, not multi-tenant, not an agent runtime.
