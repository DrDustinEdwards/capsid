### CA-1. Major. The default branch needs a pull request, zero reviews, and no status check, and a merge deploys

- Area: 12, supply chain, and 15, CI
- Confidence: high
- Where: ruleset 24044205, "default branch: pull requests only", on `~DEFAULT_BRANCH`. Prior U1.

Classic branch protection on `master` returns 404. The active ruleset's only rule is `pull_request` with `required_approving_review_count: 0`, `require_code_owner_review: false`, an empty reviewer list, and no status-check rule. Bypass is `RepositoryRole` actor id 5, mode `always` (the admin role). An admin can push straight to `master`. A non-admin must open a pull request and can merge it with no review and no green CI. `ci.yml` deploys on a merge to `master`.

Dependabot security updates are disabled. Secret scanning is on. Push protection is on. Non-provider patterns are off. Validity checks are off. The repository is public.

Path: an admin pushes a workflow or a lockfile change to `master`, or a collaborator merges an unreviewed pull request. The next deploy ships it.

Smallest fix: require one approving review and the CI checks job on the ruleset. Limit the admin bypass to a break-glass mode. Turn Dependabot security updates on.

### CA-2. Major. The MCP server package is inside two high advisories, and one of them still applies to an authenticated caller

- Area: 2, MCP, and 12, supply chain
- Confidence: high
- Where: `package.json` dependency `@modelcontextprotocol/server` 2.0.0. Lockfile override pins `@modelcontextprotocol/sdk` to 1.32.1. `src/mcp-handler.ts`. Prior S4 stays fixed.

`npm audit` and the open Dependabot alerts name:

- High GHSA-jm63-cq47-j5jp, server 2.0.0 through 2.2.0. A shared transport can deliver one HTTP client's messages to another. Patched in 2.3.0. The advisory says `createMcpHandler` with a factory that builds a new server per call is outside the affected pattern.
- High GHSA-46jr-4wx8-v453. One request inside the default body size can exhaust memory during validation. Affected server versions are >= 2.0.0 and < 2.3.0, and SDK versions >= 1.3.0 and < 1.32.0. This tree's SDK pin is 1.32.1, which is outside the SDK range. The server package is still 2.0.0. The advisory says the element cap is off by default, so a version bump alone does not enable it.
- High on `agents` 0.20.1 through 0.28.0 through the same server. This tree pins `agents` 0.24.0.

`serveMcp` builds `const factory = () => build()` and passes that factory to `createMcpHandler`. `build()` constructs `new McpServer` inside the factory. The agents stateless handler calls the factory and constructs a new transport per POST. The legacy path does the same. That matches the advisory's unaffected pattern for the cross-client bug. This pass did not try to reproduce a cross-client delivery.

GHSA-46jr still describes this server version. A caller who can put a body on the MCP parser can try to exhaust memory. That caller is an agent key on `/ops/mcp` or an Access session on `/mcp`. Live `GET /mcp` with no token is 401 and `no-store`. This is not an anonymous exploit. Other routes cap bodies at 16 KB, 64 KB, or 1 MB. No separate cap was found on the MCP route itself.

`origin/renovate/npm-modelcontextprotocol-server-vulnerability` exists. This pass did not merge it and did not treat it as reviewed.

Smallest fix: upgrade `@modelcontextprotocol/server` to >= 2.3.0 and set `maxToolInputElements`.

### CA-3. Major. A write-grant caller can complete a queued job by naming any pull request on a mapped repo

- Area: 4, data integrity
- Confidence: high
- Where: `src/jobs-seat.ts` `completeUnclaimed` (lines 213-236) and `src/job-outcomes.ts` `verifyEvidence` (line 326). Prior M3.

`completeUnclaimed` runs for a queued job nobody holds. The caller needs the write grant on the job's namespace, `required_flags`, and `min_record`. Each named URL must parse as a pull request and `resolveRepo` must map it to the namespace. The function then calls `completeWithoutClaim`. It does not require the pull request body, the branch name, or a `job_outcome_prs` row to name this job id. The comment says the pull request is the claim, from a 2026-10-10 decision.

`verifyEvidence` says it never fails the job. When GitHub is unreachable or disagrees, the outcome records the driver's numbers, marked unverified.

`recordAsCaller` still requires `callerIsSeat`. That path is a different action.

Path: a write-grant agent in the namespace calls complete on a queued job and passes the URL of any open or merged pull request on a mapped repo. The job becomes done. Auto-merge's `body_names_job` check is the binding this path does not use.

Smallest fix: before `completeWithoutClaim`, require the pull request body or a recorded `job_outcome_prs` row to name this job id.

### CA-4. Major. `LIKE 'archive/%'` treats a mixed-case prefix as archived, and JavaScript does not

- Area: 4, data integrity
- Confidence: high
- Where: `src/namespace-delete.ts` lines 121, 122, 171, and 408. The same predicate is in `src/tools/docs-read.ts` lines 136 and 142, `src/tools/lint.ts` lines 79 and 161, `src/tools/namespaces.ts` line 36, and `src/stale-canon.ts` line 384.

SQLite `LIKE` folds ASCII case unless `case_sensitive_like` is set. This tree never sets that pragma. `path NOT LIKE 'archive/%'` therefore matches `Archive/notes.md`. `pathProblem` in `src/limits.ts` accepts that path: it rejects empty, absolute, `..`, `//`, and controls, and it does not case-fold. JavaScript archive checks stay case-sensitive (`startsWith("archive/")` in `src/counts.ts`). The delete header defines a live document as any path outside `archive/` and keeps archived rows on purpose. The policy documents in the same planner are already matched with `substr`, which is case-exact.

`test/fakes.ts` implements the filter as `!path.startsWith("archive/")`, so a unit test deletes the row as live and never sees the production classification.

This pass did not execute D1. The conclusion rests on the SQL in the file, on SQLite's ASCII folding for `LIKE`, and on the absence of `case_sensitive_like`.

Path: a write-grant caller writes `Archive/notes.md`. The brief omits it. `capsid_read_doc` still returns it. An admin `delete_preview` counts the row in `documents_archived` and leaves it out of `live_paths`. `delete_perform` with `cascade: true` deletes the namespace row and the live paths, and the documents row remains. Registering the same name again brings the row back as a document JavaScript does not treat as archived.

Smallest fix: use the case-exact `substr(path, 1, 8) = 'archive/'` test already used for the policy prefix, in the delete counts, the live-path select, the plan guard, the brief, lint, the unconsolidated count, and stale-canon. Make the test fake use that predicate. Refuse in `pathProblem` any path whose lowercase form starts with `archive/` unless the stored prefix is exactly `archive/`.

### CA-5. Major. `resources/list` and `prompts/list` never call `checkScope`

- Area: 2, MCP
- Confidence: high
- Where: `src/resources.ts` lines 64-71 and `src/prompts.ts` lines 26-39. Registered on the non-admin server in `src/server.ts` lines 116-119, which is what `/ops/mcp` serves.

`resources/list` requires `grants` to include `read`, then returns `uri`, `name`, and `title` for documents in the caller's namespaces. The namespace predicate is inside the query. `prompts/list` requires the read grant, selects every `type = 'prompt'` row including `body`, filters to the caller's namespaces in JavaScript, and returns the name, a sanitized title, and the `{{placeholder}}` argument names taken from the body. The response does not include another namespace's rows. The prompt query still reads every prompt body into the worker before that filter.

`resources/read` and `prompts/get` go through `resourceRefusal`, which is `checkScope` on `capsid_read_doc` action `read`. `benchRunRefusal` runs only inside `checkScope`. The comment in `src/resources.ts` says these handlers are checked as `capsid_read_doc` so a tools-narrowed agent loses both surfaces. The list handlers do not do that.

Path 1: `POST /bench/start` with `BENCH_SECRET` arms a treatment run. The run key resolves as grants `read` and `write`, namespaces `["bench"]`, tools `["capsid_work_jobs"]`, `admin: false` (`src/bench-run-key.ts`). Its successful tool calls are claim and list of its one job. The model calls `resources/list` and `prompts/list` on `/ops/mcp` with that bearer. It receives every bench document path and title, and every bench prompt name plus placeholder names derived from the body. `resources/read` and `prompts/get` still refuse, so document bodies and prompt text stay behind `resourceRefusal`.

Path 2: an agent whose `tools` list omits `capsid_read_doc`, while `grants` still includes `read`, calls the same two methods. Default scopes use `tools: "*"`, so this is the narrowed case. It enumerates paths, titles, and prompt placeholder names inside its namespaces.

Smallest fix: at the start of both list handlers, call `checkScope(agent, { tool: "capsid_read_doc", action: "read", grant: "read" })` and refuse before the query. Keep the namespace filter. Stop selecting prompt bodies once names and titles are all the list needs.

### CA-6. Minor. GitHub installation tokens sit in KV as plaintext

- Area: 3, secrets
- Confidence: high

### CA-7. Minor. Two limits are check-then-put

- Area: 6, reliability
- Confidence: high
- Where: `src/rate-limit.ts` lines 1-8, and `src/site-repair.ts` lines 95-99. Prior S5 for the first site.

The rate limiter reads both counters, compares, then writes `count + 1`, with no compare-and-swap. The file says a burst can pass somewhat over the cap and that nothing may rely on it as an exact ceiling. CSP reports use `onUnavailable: "refuse"`.

`runSiteRepair` reads the limit, checks it, writes the next value, then POSTs. The comment says writing the limit before the call stops a race. Two overlapping callers can both pass the check and both POST.

Smallest fix: take the slot with a write that matches the previously read count, and send the call only when that write changes a row. Keep the rate limiter's documented bound, and keep CSP reports fail-closed.

### CA-9. Minor. A second complete dump on the same UTC day prunes the earlier one immediately

- Confidence: high

### CA-15. Minor. Auto-merge reads one page of 100 open pull requests and rewrites the seat queue from that page
