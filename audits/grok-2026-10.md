## Threat model (STRIDE)

Capsid is one Cloudflare Worker. It holds the portfolio knowledge base (D1 `documents` and history, R2 backups and the markdown mirror, KV for OAuth, rate limits, installation tokens, and pins) and it holds a GitHub App key that can mint a repo-scoped installation token. It also holds Cloudflare, Search Console, Bing, Access-sync, and site-operator credentials, and it can merge pull requests when a signed policy says so.

Who can call it:

- An anonymous browser, for `/health`, the public JSON documents, the OAuth metadata and consent pages, `/register` (allowlisted redirects only), `/csp-report`, and the public explorer on `capsid.dustinedwards.info`.
- A person who passes Cloudflare Access as `ADMIN_EMAIL` or an entry in `CO_OWNER_EMAILS`, for the Portal and for MCP on `/mcp`. Admin actions that change who may act also need a fresh step-up.
- A minted agent key, for `/ops/mcp`. The row's scopes are the grant. `admin` on a minted row is false. Drivers are minted with no `can_merge`.
- The operator key whose sha256 is in `OPERATOR_KEY_HASH`. A write entry is an admin with every flag and no step-up. A `ro:` entry is read-only. This is the break-glass seat.
- The five-minute cron, the 09:00 UTC backup cron, and the skills-refresh cron. They run as the Worker, with the App and the store, and with no end-user session.
- GitHub Actions on this repo, which holds the Cloudflare deploy token and the live-probe key. A merge to `master` deploys.

Entry points: `/mcp` and `/mcp/admin` (Access OAuth), `/ops/mcp` and `/ops/mcp/admin` (bearer), `/portal/api/*` (Access session plus CSRF), `/ops/backup`, `/ops/access-sync`, `/ops/inbox`, `/ops/hooks`, `/ops/otlp/v1/*`, `/bench/*` (HMAC), `/backup/credential` (HMAC), `/register`, `/authorize`, `/token`, `/csp-report`, the public JSON routes, and the three crons. There is no queue consumer in the Worker.

Trust changes at `resolveAgent` (bearer to an agent), `checkScope` (agent to an action), `portalGate` (cookie to the admin email), the OAuth consent screen (admin approval to a `redirect_uri`), `guardedWrite` (tool to a GitHub mutation plus an audit row), the signed auto-merge policy (cron to `managePr`), and `signedBody` (bench and backup HMAC). Document bodies, pull request text, and job summaries are data that a later model call will read. That is the injection boundary.

### Findings

#### C1. Critical. Portal path `//` becomes an off-origin redirect, and an OAuth code can ride it

Severity: CRITICAL. Confidence: confirmed for the redirect and for the provider's acceptance of the URI. The live token exchange was not run.

Files: `src/portal-host.ts:41-58`, called from `src/index.ts:109-110` before the OAuth provider. Post-login sink: `src/portal-auth.ts:131-135`. Provider check: `validateRedirectUri` in `@cloudflare/workers-oauth-provider` accepts any `https` URI with no userinfo and no fragment.

`publicPortalPath` strips a leading `/portal` and returns the remainder. `new URL("//attacker.example", "https://portal.dustinedwards.info")` is `https://attacker.example/`. The same parse turns a backslash into a slash, so `/portal/\attacker.example` arrives as `/portal//attacker.example`. A local `node` check printed `https://attacker.example/` for both shapes.

Caller path: a CIMD client whose metadata lists `redirect_uris: ["https://portal.dustinedwards.info/portal//attacker.example"]`. The consent dialog shows that string (`src/routes.ts:136`). After the admin approves, the provider sends the browser to that URL with the authorization code. This Worker answers 308 to `https://attacker.example/?code=...`. The client that started the flow holds the PKCE verifier and can redeem the code at `/token`. The grant on that flow is the admin's. The session cookie is host-only, so the redirect alone does not forward the cookie. The code is the thing that leaves.

A visit to `https://portal.dustinedwards.info/portal//attacker.example` is the same 308 with no login. That one is a phishing redirect. The callback path has the same slice: `isPortalPath` accepts `/portal//attacker.example`, and `Location` is then the protocol-relative string.

Smallest fix: after the slice, accept only a path that matches `^/(?!/)`. Resolve it with `new URL(path, origin)` and require the result's origin to be this host. Do that for the 308 and for the post-login `Location`.

#### M1. Major. A namespace sync key can clear a Zero Trust seat it never managed

Severity: MAJOR. Confidence: confirmed.

File: `src/access-sync.ts:271-289`. Gate: `syncCallerRefusal` is `checkScope` write on the namespace (`src/access-sync.ts:147-148`). The group id comes from `access_sync_groups`, not from the body.

`toFree` is `req.removed` minus the new member list. It is not intersected with the group's previous include list. `seatsFor` looks the email up on the account users API and the PATCH sets `access_seat: false` and `gateway_seat: false`.

Caller path: `POST /ops/access-sync` with a write-grant agent for a namespace that has a pin. Body `{ namespace, members: [current list], removed: ["person@example.com"] }`, up to 100 removed emails. The group write can be a no-op (members unchanged). The seat PATCH still runs for anyone absent from `members`.

Smallest fix: free a seat only when the email was in the previous include list, is in `removed`, and is absent from the new list.

#### S1. Major. A second write-grant agent can clear a human gate

Severity: MAJOR. Confidence: confirmed. Area: authorization, and MCP excessive agency.

File: `src/jobs-seat.ts:598-607`. The comment at `462-472` states the rule the code implements: any write-grant caller may plain-resume, and the claimant may not resume itself.

`approved_by_policy` is narrowed for a driver (`src/jobs-seat.ts:680-701`) to `push_branch` and `open_pr` on a job that driver still holds. A plain resume has no such class check. A sibling driver with write on the namespace supplies a reason and the job leaves `blocked`. The audit action is `resume`. The mirror then shows that note to the next session.

Caller path: `capsid_work_jobs` action `resume` on a job blocked for a deploy, a secret, a force-push, or a shell command, by an actor other than the claimant.

Smallest fix: require `callerIsSeat` (admin or `can_merge`) for a plain resume. Keep `approved_by_policy` for the holder's own push and pull request.

#### S2. Major. `openWorldHint: false` on a tool that closes pull requests and calls site APIs

Severity: MAJOR for a client that treats a closed-world tool as local. The tool is admin-only, and `destructiveHint` is true. Confidence: confirmed.

Files: `src/tool-annotations.ts` (the controls hint and the comment "Only this Worker's own stores"), `src/controls.ts:398` (`managePr` close), `src/controls.ts:550-556` (site repair POST), `src/approval-executor.ts:137` (merge after `approve_pr`). `test/tool-annotations.test.ts` walks direct imports and its `OPEN_WORLD_THROUGH` list has no `controls` entry, so the hint and the test agree with each other.

Caller path: `capsid_admin_run_controls` action `perform`.

Smallest fix: set `openWorldHint: true` and add the controls operations to the annotation test's allowlist, with `managePr(` and `runSiteRepair(` as the evidence.

#### S3. Minor. GitHub installation tokens sit in KV as plaintext

Severity: MINOR. Confidence: confirmed.

File: `src/github/client.ts:98-114`. The cached value is the token string. The mint body is `{ repositories: [repo] }`. The metadata token in `listInstalledRepos` stays in a local variable. The backup KV sidecar is an allowlist (`backup:last-ok` only).

A reader of `APP_KV` gets a live one-repo token until the TTL. The App private key stays a Worker secret.

Smallest fix: encrypt with a Worker secret before `put`, or mint per isolate and skip KV.

#### S4. Minor. The unpatched MCP SDK copy is still installed

Severity: MINOR. Confidence: confirmed for the audit output and for the absence of an SDK OAuth-client import in `src`. The internals of `agents/mcp/server` were not fully traced.

`npm audit` reports `GHSA-6qxp-vccf-f47h` on `sdk@1.30.0` via `agents@0.24.0`. The bug is an OAuth client sending `refresh_token` and `client_secret` to a server chosen by a malicious MCP server. This Worker is an MCP server. The patched client 2.2.0 is the direct dependency. `npm audit fix --force` wants `agents@0.28.1`.

Smallest fix: move `agents` to a release whose SDK is at least 1.31.0, or add an override once that version loads.

#### S5. Minor. KV rate limits are check-then-put

Severity: MINOR. Confidence: confirmed.

File: `src/rate-limit.ts` (read counters, then write `count + 1`). Concurrent requests can all see the same count. A KV read or write failure refuses, for every policy that was read (`dcr`, access-sync, public data, csp-report). `claimJti` uses an atomic insert for replay, which is the stronger pattern.

Caller path: parallel `POST /register` from one address. The redirect allowlist still applies, so the extra registrations do not grant a token.

Smallest fix: an atomic counter, or document the ceiling as best-effort.

#### S6. Minor. The Access login state cookie is `sha256(state)`, and `state` is in the callback URL

Severity: MINOR. Confidence: confirmed by the auth pass, re-checked against the described lines.

File: `src/access-login.ts` sets the cookie to `sha256Hex(stateToken)` and compares it the same way. Anyone who has the callback URL before the KV row is spent can recompute the cookie. `Referrer-Policy: no-referrer` is on the responses that were fetched. PKCE for the MCP flow is held by the Worker, in KV.

Smallest fix: store a random cookie value in the KV record and compare that.

### Findings

#### M2. Major. A write can replace a job mirror, and the next brief serves that body beside the rules

Severity: MAJOR. Confidence: confirmed.

`ruleDocCap` (`src/rule-docs.ts:8`) excludes `jobs/`. `capsid_write_doc` will store a body at `jobs/<id>.md`. Brief loads every non-closed `type = 'task'` outside `archive/` and returns the body (`src/tools/docs-read.ts:136`). Claim later checks the signed row and fails a signature mismatch. The brief has already been read.

Caller path: `capsid_write_doc` on `jobs/<id>.md` in a namespace the caller can write, then another session's brief in that namespace.

Smallest fix: refuse write, delete, move, and restore of `jobs/*.md` except through the mirror writer. Have brief render the mirror only when the body matches the signed row.

#### M3. Major. A queued job can be marked done by naming any pull request on a mapped repo

Severity: MAJOR. Confidence: confirmed.

File: `src/jobs-seat.ts:214-237`. `resolveRepo` checks that the URL's repo is mapped to the namespace. It does not check that the pull request names the job, that the caller opened it, or that GitHub says it merged. `verifyEvidence` records notes and does not fail the transition (`src/jobs-holder.ts:178-180`). `review_required` still goes through `seatReviewRefusal`. Jobs without that flag do not.

The comment at `201-213` describes this as the intended "pull request is the claim" path for a cloud session that signs in as admin. The check that was shipped is weaker than that sentence: any mapped pull request URL is enough, and an unread GitHub still lets the row go to `done`.

Caller path: `capsid_work_jobs` action `complete` when status is `queued` and `claimed_by` is null.

Smallest fix: refuse `complete-unclaimed` unless GitHub reports the pull request merged and its body or branch names the job id.

#### M4. Major. A driver edge can mark canon superseded

Severity: MAJOR. Confidence: confirmed.

`parseLinks` (`src/links.ts:40`) accepts any `to_ns` that is a namespace name. `capsid_write_doc` inserts those edges from a source the caller can write (`src/tools/docs-write.ts:257-272`). `supersedePass` (`src/supersede.ts:32-60`) runs on the backup cron, snapshots the target, sets `status` to `superseded`, and audits as `system:supersede-pass`. It does not skip canon paths. Search hides `superseded` by default. The body stays. The pass does not reverse itself.

Caller path: a write-grant driver publishes a note whose `supersedes` or `replaces` edge points at `capsid/conventions.md` or a namespace `core.md`. The next daily pass marks that target.

Smallest fix: skip canon paths in `supersedePass`, or refuse those two edge types onto a canon path unless the caller is the seat.

#### J1. Major. A job's own `model:` line overrides a high-risk rule

Severity: MAJOR. Confidence: confirmed. The Worker recommends a model. It does not start the session. Sessions are told to follow `model_recommended`.

File: `src/model-routing.ts:273-279`. `named` wins over the risk rule, including haiku on a high-risk job, and it skips the trial. `docs/work-queue.md` says risk can only go up.

Caller path: `capsid_work_jobs` `post` with a signed body that contains a line `model: haiku`, then `claim`, which routes again.

Smallest fix: when risk is high, ignore a named model that is weaker than the risk rule.

#### J2. Major. Pull request risk uses one page, and anything short of high is discarded

Severity: MAJOR. Confidence: confirmed.

`pullRequestRisk` (`src/model-routing-pr.ts:12-22`) requests `per_page=100`. A failed read returns `risk: null`. `riskOf` on an empty list is `unread` (`src/model-routing.ts:105`). `routeJob` keeps `pr_risk` only when `level === "high"` (`src/model-routing.ts:273`). A money or refused path past file 100, or a read that failed, leaves the route on the job's own text, which can be routine.

Caller path: `claim` on a job that already names a pull request.

Smallest fix: treat a failed read, an `unread` result, and a full page as high, and page until the file list ends.

#### J3. Major. Bench score picks the attempt again, with a different stale cutoff
